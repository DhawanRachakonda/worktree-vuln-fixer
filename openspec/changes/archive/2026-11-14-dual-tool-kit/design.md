# Design

## Context

`KitInstaller.java` (one file, JDK only) copies `.github/{agents,skills,instructions,prompts,modernize/rulebook,appmod/tools}` of the kit into a
target repository (or into `~/.copilot` with `--user`), merges `copilot-instructions.md` as a marked block, and appends `.appmod/` to `.gitignore`.
`appmod.cmd init` calls it and passes extra arguments through. The agents use Copilot's lower-case tool aliases (`read`, `search`, `edit`,
`shell`, `agent`) and the Copilot-only key `user-invocable`. Claude Code reads subagents from `.claude/agents/<name>.md` (required `name` and
`description`, optional `tools` as a comma list or a YAML list, unknown keys ignored), skills from `.claude/skills/<name>/SKILL.md`, rules from
`.claude/rules/`, memory from `CLAUDE.md`, MCP servers from `.mcp.json`. `appmod-harness` delegates to `github-copilot-modernization:modernize`, a
Copilot plugin.

## Goals / Non-Goals

**Goals:** one set of sources; Claude Code files generated by the installer; Copilot installs unchanged; safe, repeatable installs.
**Non-Goals:** a Claude version of the front door `appmod-harness` (needs a design of its own around the MCP server's tools), converting the
prompt files, and packaging the kit as a Claude Code plugin.

## Decisions

- **The existing `.github` files stay the source; Claude files are generated.** The earlier idea was a neutral source (frontmatter with
  names valid in both tools). That needs Copilot CLI to accept Claude's tool names, which was never verified, and it would change every
  agent that works today. Rendering from the current files changes nothing for Copilot and is a small, testable function.
- **Tool mapping is a table and an unknown name is an error.** Silently dropping a tool would give an agent more or less power than its
  author wrote; failing at install is cheap. The mapping: `read`: `Read`; `search`: `Grep`, `Glob`; `edit`: `Edit`, `Write`; `shell`: `Bash`, `PowerShell`;
  `agent`: `Agent`. `PowerShell` is listed even on systems without it: Claude Code only fails when no entry resolves.
- **Frontmatter is rewritten line by line, not through a YAML library** (no dependencies in the installer): the kit's agents use `key: value`
  lines and one flow list for `tools`; anything else is a refusal with the agent's name, so a future format change is noticed.
- **Path rewrite is a fixed list of three prefixes** (`.github/agents/`, `.github/skills/`, `.github/instructions/appmod-harness.instructions.md` to
  `.claude/rules/appmod-harness.md`), applied to agents, skill text files and rules. `.github/appmod/tools/` and `.github/modernize/rulebook/`
  are installed for both tools in the same place, because the agents run those tools by path and the files are tool-neutral; no rewrite is needed.
  A test checks that no generated file refers to the three prefixes any more.
- **`CLAUDE.md` gets a fixed text block**, not a transformed `copilot-instructions.md`, because that file's first instruction (start with
  `appmod-harness`) is false for Claude Code.
- **`appmod-harness` is skipped with a visible report line.** Rendering it would install an agent that cannot do its job.
- **Both tools together duplicate the skills** (`.github/skills` and `.claude/skills`). Checked with the real Copilot CLI: it lists each skill once. It also
  reads `.claude/agents` and lists each agent once, and the path it names for them is the `.claude` one, so with both installed Copilot may be using the
  rendered agent files; not investigated further.
- **The record is the installer's own file, not a lock file the person edits.** `.appmod/kit.json` holds the tool and one SHA-256 per placed file; `--upgrade`
  overwrites a file only if it still hashes to the recorded value, which is how "nobody edited it" is decided without a version number. A file the person
  edited keeps its old recorded hash, so it stays "edited" until they accept a replacement with `--force`. Merged files (`CLAUDE.md`,
  `copilot-instructions.md`, `.gitignore`) are not recorded: they hold the person's own text.
- **`validate-run.cjs` looks in both places** instead of the installer rewriting the tool: the fix is one line, and it is the only kit tool with a skill path.
- **`appmod.cmd` asks only for a new install** (no record, no `--tool`, no `--yes`); with a record it upgrades as recorded.
- **Default stays `copilot`**, so `appmod.cmd init` and every existing script keep working.

## Risks / Trade-offs

- Generated agents were checked against Claude Code's documented format, by listing them with the `claude` CLI, and by two real runs (`security-fixer`
  37 of 37 checks; `security-audit` all five planted flaws at their lines); one run of a model proves little about the next.
- A person who edits a generated file keeps it (no overwrite without `--force`), so after a kit upgrade they must compare by hand, as for Copilot.
- The rendered text still names Copilot where the source does (for example `appmod-harness` in the fixer's description); harmless, not rewritten.
