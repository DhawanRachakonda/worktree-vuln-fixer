Real engine run, 2026-11-15, Windows 11. Change: source-branch-and-pull-request.
What is real: the engine jar (java -jar subscriber-engine-0.1.0-SNAPSHOT.jar, console off), a NATS server in Docker (nats:2.10-alpine), the real nats command-line client (natsio/nats-box image) publishing with message headers,
real git (a sample Spring Boot project, files only, with a bare origin whose default branch is develop, and the checkout on feature/wip with uncommitted work), the engine's own read API for the results.
What is a stand-in: the coding agent (a program that commits one file and writes result.json) and the pull-request command (a program that prints a link). No hosted git service, gh or glab. No terminal console (the engine refuses a console without a terminal).

## Defect this run found (fixed, with a regression test): a local-changes session ended ERROR in a repository where appmod init had put .appmod/ in .gitignore
reason shown by the engine before the fix: 'the worktree could not be created: git could not collect the local changes: warning: in the working copy of pom.xml ...' (only git's first line, a harmless line-ending warning)
the real cause, reproduced by hand with the same command on a temporary index:
$ git add -A -- . ":(exclude).appmod"        (the .gitignore of the repository contains .appmod/)
warning: in the working copy of 'pom.xml', LF will be replaced by CRLF the next time Git touches it
The following paths are ignored by one of your .gitignore files:
.appmod
hint: Use -f if you really want to add them.
exit=1
fix: add without a pathspec, then remove .appmod from the temporary index; error text now shows git's own error line.
